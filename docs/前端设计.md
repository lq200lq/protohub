## 1. 技术基线与项目裁剪

### 1.1 从 vben 保留 / 删除 / 新增

| 操作 | 内容 |
| --- | --- |
| 保留 | `apps/web-antd` 整体结构、`packages/@core/*`、`packages/effects/{access,request,common-ui}`、`packages/stores`、主题与 i18n 机制、`apps/backend-mock`（仅作为接口对照参考，不用于本项目运行） |
| 删除 | `apps/web-ele`、`apps/web-naive`、`apps/web-tdesign`、`apps/web-antdv-next`、`apps/playground`、`docs`、所有 demo 页面（`views/demos/**`）、`views/dashboard/analytics` 等示例 |
| 新增 | `views/dashboard/workspace`、`views/proto/**`（项目列表/项目详情/原型详情/上传发布/访问记录）、`views/system/setting`、`views/_core/profile`、`api/proto/**` 与 `api/system/**` 业务 API 模块 |

> 保留 `apps/backend-mock` 的唯一理由：它是 vben 官方 mock，用来在联调出现分歧时**对照框架期望的请求/响应形态**（例如 `refresh` 为什么返回裸字符串）。它不在任何部署链路里。

### 1.2 环境变量

```bash
# apps/admin/.env
VITE_APP_TITLE=HTML 原型托管平台
VITE_APP_NAMESPACE=protohub-admin
VITE_APP_STORE_SECURE_KEY=<部署时生成的随机串>

# apps/admin/.env.development
VITE_PORT=5671
VITE_BASE=/
VITE_GLOB_API_URL=/api
VITE_NITRO_MOCK=false          # 关键：关掉 mock，走真实后端
VITE_DEVTOOLS=true

# apps/admin/.env.production
VITE_BASE=/
VITE_GLOB_API_URL=/api          # 与 nginx 同域，nginx 反代到 Node
VITE_ROUTER_HISTORY=history     # 默认是 hash，本项目改 history（需 nginx fallback）
VITE_COMPRESS=brotli
VITE_ARCHIVER=false             # 不需要 dist.zip 这点体积收益
VITE_INJECT_APP_LOADING=true
```

> `VITE_GLOB_*` 变量在打包时会写进 `dist/_app-config-*.js`，生产环境改 API 地址不必重新打包。

## 2. 信息架构

侧边栏沿用原型图（**扁平一级菜单**，不用二级目录）。三级结构体现在**页面内部的下钻**，不体现在侧边栏嵌套——每天在动的是原型，把它埋进三级侧栏只会增加点击成本。

```
侧边栏（扁平，与截图一致）                页面内的下钻
────────────────────────────────────    ───────────────────────────────────
工作台          /dashboard/workspace     看整体情况 + 最近更新的原型
原型项目        /proto/project           项目列表 ──点击项目名──▶ 项目详情（含原型列表）
上传发布        /proto/publish                                 ──点击原型名──▶ 原型详情
访问记录        /proto/accesslog          项目详情 / 原型详情都从这里取数（带筛选参数）
设置            /system/setting           页内 Tabs：账号安全 / 用户 / 角色 / 菜单 / 日志
```

三级对象与页面的对应关系：

| 层级 | 列表在哪 | 详情在哪 | 关键动作 |
| --- | --- | --- | --- |
| 项目 | 侧栏「原型项目」 | `/proto/project/detail?id=` | 新建/编辑/归档/删除项目，看原型列表 |
| 原型 | 项目详情的原型列表 | `/proto/prototype/detail?id=` | **上传发布、复制链接、设访问策略、回滚、归档** |
| 版本 | 原型详情的版本记录 | 无独立页面（在原型详情内） | 回滚、删除版本、查看发布报告 |

**为什么"设置"是单页 Tabs 而不是二级目录**：原型图上它是一个带齿轮图标的单条目，且系统管理类配置在内部平台里访问频率低，做成 Tabs 可以让权限控制下沉到 Tab 级（无权限的 Tab 不渲染），比二级菜单更少层级。

## 3. 页面清单

| 路由 | 视图文件 | 标题 | 菜单可见 | 主要权限码 |
| --- | --- | --- | --- | --- |
| `/dashboard/workspace` | `views/dashboard/workspace/index.vue` | 工作台 | ✓（affixTab） | `dashboard:workspace:view` |
| `/proto/project` | `views/proto/project/index.vue` | 原型项目 | ✓ | `proto:project:list` |
| `/proto/project/detail` | `views/proto/project/detail/index.vue` | 项目详情 | ✗（hideInMenu） | `proto:project:read` |
| `/proto/prototype/detail` | `views/proto/prototype/detail/index.vue` | 原型详情 | ✗（hideInMenu） | `proto:prototype:read` |
| `/proto/publish` | `views/proto/publish/index.vue` | 上传发布 | ✓ | `proto:prototype:publish` |
| `/proto/accesslog` | `views/proto/accesslog/index.vue` | 访问记录 | ✓ | `proto:accesslog:list` |
| `/system/setting` | `views/system/setting/index.vue` | 设置 | ✓ | 按 Tab 细分 |
| `/profile` | `views/_core/profile/index.vue` | 个人中心 | ✗（hideInMenu） | 仅需登录 |
| `/auth/login` | vben 内置 | 登录 | ✗ | — |

`hideInMenu` 由 vben 的菜单生成读取（`packages/utils/src/helpers/generate-menus.ts` 中 `show: !meta.hideInMenu`），因此隐藏路由也走后端菜单表，前端不额外写静态路由。

> **详情页用 query 传 id（`?id=9`）而不是路径参数（`/proto/project/9`）**：vben 的后端菜单驱动的动态路由对 `:id` 形式的子路由在 redirect 推导上有已知坑（fork 里有专门补丁注释）。用 query 传参完全绕开这条路，且"详情页从列表进入、不进侧栏"的语义一致。

### 3.1 工作台（`/dashboard/workspace`）

对应原型图未展示（首屏落点），按"先看结论、再进入操作"设计：

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| 顶部统计卡 | 项目数 / 原型数 / 本周发布次数 / 近 7 天访问量（含环比小字） | `GET /api/dashboard/overview` |
| 最近更新的原型（左，占 2/3 宽） | 5 行：原型名 + 所属项目 + 状态标签 + 近 7 天访问量 + 相对时间；点击进原型详情 | 同上 `recentPrototypes` |
| 最近动态（右，占 1/3 宽） | 10 条版本事件时间线：谁在什么时候发布/回滚了哪个项目的哪个原型 | 同上 `recentEvents` |
| 主行动按钮 | 「上传 HTML 原型」（右上，打开 §3.4 抽屉） | 需 `proto:prototype:create` |

> 统计卡的四个数字里放**原型数**而不是"已发布项目数"：项目是容器，一个项目建完就不怎么变了，原型数才是真实工作量。

### 3.2 项目列表（`/proto/project`）—— 主力页面

**布局（对齐原型图，但因模型变成三级，列有调整）**

```
┌ 页面头部 ────────────────────────────────────────────────────────────┐
│ 原型项目            上传静态 HTML 原型文件，立即获得可访问的在线链接，   │  [上传 HTML 原型]
│                     方便团队查看与评审。                                │
├ 列表 ────────────────────────────────────────────────────────────────┤
│ 项目名称        项目编码    原型数        最近更新        状态      操作 │
│ CRM系统         crm        6 (已发布 5)  2026-10-06 14:30 已发布    ⋯ │
│ 招聘系统        recruit    3 (已发布 3)  2026-06-11 10:24 已发布    ⋯ │
│ 招投标平台      bid        2 (已发布 0)  2026-06-08 16:20 草稿      ⋯ │
│ ...                                                                    │
└──────────────────────────────────────────────────────────────────────┘
```

**列定义**

| 列 | 宽/对齐 | 呈现规则 |
| --- | --- | --- |
| 项目名称 | 自适应，左对齐 | 名称主文本加粗，**可点击进项目详情**（这是进入下钻的主入口）；不堆说明文案 |
| 项目编码 | 固定 140px | 等宽字体（`font-mono`），便于肉眼比对 |
| 原型数 | 固定 140px | `6` 主文本 + `(已发布 5)` 次级小字；为 0 时显示「暂无原型」并带一个「上传」小链接 |
| 最近更新 | 固定 140px | 两行：日期 + 时间；排序字段（默认 `desc`）。语义是"该项目下任一原型的最近发布时间"，没有发布过则取项目更新时间 |
| 状态 | 固定 100px | 派生 Tag：已发布=绿、草稿=橙、已归档=灰（`status` 是后端算出的派生值，前端不做二次判断） |
| 操作 | 固定 80px | 单个「⋯」下拉，不排一排按钮（见 §10.3） |

**与原型图的差异（重要）**：原型图里项目行有「访问地址」列，但三级模型下一个项目对应**多条**链接，在一行里放任一条都会误导。因此该列改为「原型数」，访问地址下移到项目详情的原型列表里（每行一个地址，语义准确）。这是模型变化带来的必要调整，不是实现取舍。

**筛选与搜索**：列表页工具栏左侧放关键字输入框（项目名称/编码模糊）、状态下拉；排序走表格列排序（`sortBy`/`sortOrder`）。

> **与原型图的另一处刻意偏离**：原型图里的搜索框画在**顶部全局 header**。一期把搜索放在列表页工具栏，不改 vben header 结构（header 是框架公共区，改它会影响所有页面，收益只是"少一次点击"）；二期若确实需要全局搜索再上提。此偏离记入 §13。

**行内操作菜单（「⋯」）**

| 菜单项 | 显示条件 | 动作 |
| --- | --- | --- |
| 查看详情 | 恒 | 跳 `/proto/project/detail?id=` |
| 新建原型 | `proto:prototype:create` | 打开 §3.4 抽屉的「已有项目 + 新建原型」模式 |
| 编辑项目 | `proto:project:update` | 打开项目表单抽屉（名称/说明；编码只读） |
| 归档项目 | `proto:project:archive` 且非归档 | 二次确认（说明"其下**所有原型**的链接都将不可访问，产物保留"——这句必须写清影响面，否则用户以为只影响项目本身） |
| 删除项目 | `proto:project:delete` | 危险确认，要求输入项目名称确认（含全部原型与版本产物，不可逆） |

**空状态**：无项目时展示插画 + 「上传第一个 HTML 原型」按钮（该动作会一并创建项目与原型），不留白。

### 3.3 项目详情（`/proto/project/detail?id=`）

**呈现原则：文本态优先，点「编辑」才进入表单**（避免打开页面就是一排输入框）。

| 区块 | 内容 |
| --- | --- |
| 头部 | 项目名 + 派生状态 Tag + 右侧操作（新建原型 / 编辑 / 归档 / 更多） |
| 基本信息（卡片） | 只读文本：项目名称、项目编码、项目说明、创建人、创建时间、最近发布时间。点「编辑」切换为表单（编码字段只读且带"不可修改"小字） |
| 统计条（一行） | 原型总数 / 已发布 / 草稿 / 近 7 天访问量 |
| **原型列表（主体）** | 表格：原型名称、原型编码、访问地址（可复制 + 新窗口打开）、当前版本、访问策略 Tag、状态、最近更新、操作 |
| 项目动态（右侧或下方折叠） | 该项目下所有原型的版本事件时间线（`GET /api/projects/{id}/events`），每条带原型名 |

**原型列表的行内操作**：查看详情 / 上传新版本 / 访问策略 / 复制链接 / 回滚到上一版本 / 归档 / 删除。

**字段范围约束**：详情页展示的字段 = 新建抽屉里能填的字段（名称/编码/说明）+ 系统生成信息（时间、人、统计）。**不放访问密码**（密码是敏感项，只看策略类型，改密码是独立操作）。

### 3.4 上传 HTML 原型（右侧抽屉，对应原型图右半部分）

一个抽屉承载两种模式，**按三区块分组**（字段比原来多了"原型"这一层，若不分组会变成一长条看不出主次的表单）：

```
┌ 上传 HTML 原型 ─────────────────────────────────┐
│ ① 归属项目                                      │
│    ( ) 选择已有项目  [可搜索下拉 ▾]              │
│    (•) 新建项目     项目名称* [          ]       │
│                     项目编码  [留空自动生成]     │
│ ② 原型信息                                      │
│    原型名称* [                    ]             │
│    原型编码  [留空自动生成 crm-p01]              │
│    说明（可选）[                  ] 0/200        │
│ ③ 上传文件 *                                    │
│    [ 拖拽区：支持 .zip，不超过 100MB ]           │
│                                                │
│ 发布后访问链接                                   │
│ https://proto.company.com/p/crm/crm-p01    ⧉    │
│                        [ 取消 ]  [ 立即发布 ]    │
└────────────────────────────────────────────────┘
```

| 模式 | 触发入口 | 区块 ① / ② |
| --- | --- | --- |
| 新建项目 + 新建原型 | 工作台 / 项目列表页的「上传 HTML 原型」 | ① 默认选中「新建项目」；② 需手填或留空 |
| 已有项目 + 新建原型 | 项目详情页的「新建原型」 | ① 锁定为该项目（只读展示，不可切换）；② 需手填或留空 |
| 已有原型 + 发新版本 | 原型行内「上传新版本」/ 上传发布页 | ① ② 均只读展示（原型名称/编码），只有「版本说明」可填 → 此时抽屉只有 ②的说明 + ③文件两个输入 |

**字段与交互**

| 字段 | 组件 | 规则 |
| --- | --- | --- |
| 归属项目 | Radio + 可搜索 Select | 切换 Radio 时清空/保留对应字段；「选择已有项目」下拉支持按名称与编码搜索 |
| 项目名称 | Input | 必填，≤80 字；失焦去空格 |
| 项目编码 | Input（`font-mono`） | **可留空**；留空时右侧显示灰字「留空将生成 `p-7f3k9m2x`」（值取自 `check-code` 的 `generated`）；填写时实时规范化为小写（非 `[a-z0-9-]` 的字符不落输入）并在失焦调用 `GET /projects/check-code` |
| 原型名称 | Input | 必填，≤80 字 |
| 原型编码 | Input（`font-mono`） | **可留空**；留空时显示灰字「留空将生成 `crm-p01`」——序号由后端在受理时确定（前端显示的预览可能因并发而变成 `crm-p02`，因此提示语用"将生成"而不是断言具体值）；填写时同项目编码的规范与校验 |
| 说明 | Textarea | 选填，`maxLength=200` 且显示 `0/200` 计数（与原型图一致，不额外放 hint 文案） |
| 上传文件 | 拖拽上传区 | 见下方状态机 |

> **「项目编码/原型编码可留空」是本轮的体验核心**：产品经理不必为每个原型想一个不重复的编码。界面上仍保留手填能力（用于对外保密场景，见 R-9），但默认路径是留空。
>
> **两个都留空时的编码形态**：原型编码是"项目码 + 序号"，所以项目码也随机生成时，链接会变成 `p-7f3k9m2x/p-7f3k9m2x-p01`——能正常工作但不好看也不好念。因此界面在"项目也新建且编码留空"时，把预览文案写成「项目编码留空将生成 `p-7f3k9m2x`，原型编码将生成 `p-7f3k9m2x-p01`」，让用户**在提交前就看到**这个结果；如果他希望链接好念，自然会回来填一个 `crm`。不做"自动省略前缀"这类隐式规则——那会让编码的生成规则变成两种，后续排查链接时无法从编码反推它属于哪种规则。

**上传区状态机**（`HtmlZipUploader` 组件内部）

```
idle ──选择/拖入文件──▶ 本地校验 ──通过──▶ uploading(0-100%) ──▶ pending(服务端受理)
  ▲                        │                                        │
  │                        └─不通过（非 .zip / >100MB）─▶ error ─────┘
  └──────────────────── 移除文件/重试 ◀──────────────────────────────┘
                                        │ 轮询任务
                                        ▼
                            processing(展示 stage 与百分比)
                                        │
                        ┌───────────────┴───────────────┐
                        ▼                               ▼
                    success（切"发布成功"态）        failed（展示 error + 重试）
```

- **两段进度要分开呈现**：上传进度用文件行的进度条；服务端处理进度用一条"正在校验包结构 → 正在解压 → 正在处理资源路径 → 正在切换版本"的步骤条（`stage` 字段驱动），让用户知道卡在哪一步。
- 成功后不再保留表单，改为结果态：大号成功图标 + 访问地址 +「复制链接」+「立即访问」（新窗口）+「查看原型详情」；这是"发布后立即访问该链接"的正向出口。
- 失败态展示 `error`（人话）+ 稳定错误码小字（给开发报障用）+「重试」「查看发布报告」。**重试不需重填表单**：受理阶段已落库 `draft` 原型，重试直接复用该原型的 id（对应接口设计 §5.1 的理由）。
- 关闭抽屉时若正在处理：**不阻止关闭**，改为在页面右下角显示一个持续的任务进度浮层（对应"不做无出口的等待确认态"：用户不必被锁在抽屉里等着）。

**本抽屉不包含的字段**：访问策略（密码）。原因：上传是一次性动作，密码是原型的长期属性，混进来会让"上传"承担两件事。密码在原型的「访问策略」里设置。

### 3.5 原型详情（`/proto/prototype/detail?id=`）—— 分享链接与版本的落点

这是使用者最常打开的页面（复制链接、回滚、改密码都在这里）。

| 区块 | 内容 |
| --- | --- |
| 头部 | 原型名 + 状态 Tag + **访问策略 Tag**（密码档显示"需要密码"，副标题里不显示密码本身）+ 右侧操作（上传新版本 / 复制链接 / 立即访问 / 编辑 / 更多） |
| 面包屑 | `原型项目 / CRM系统 / 登录页演示`，可点回上层（三级结构必须有面包屑，否则用户容易迷路） |
| 访问信息（卡片） | 访问地址（等宽字体 + 可复制）、访问策略（含「修改策略」入口，含"修改密码会让已获得密码的人重新输入"的说明）、近 7 天访问量（点击跳访问记录并带 `prototypeId` 筛选） |
| 基本信息（卡片） | 只读文本：原型名称、原型编码、说明、所属项目、创建人、创建时间 |
| 当前版本（卡片） | 版本号、入口文件、文件数、体积、内容指纹前 8 位、发布人、发布时间、「下载此版本」（P1） |

**字段范围约束**：只放新建时可填的字段 + 系统生成信息；**不放访问密码**。

> 修订说明（M4-T12，计划 §9.2 DEV-36）：本行原写"该原型最近 20 条**入口**访问"。`GET /api/access-logs`（接口设计 §6.1）的筛选维度只有项目/原型/时间/结果/关键字，**没有"是否入口"这一维**，前端无法按原文取数；而把"入口"去掉也不损失用途——机制 §6 里 `result='ok'` 的行本来就恰好只在入口产生（资源 200 不进统计），面板里多出来的那几行是资源级 404/403，正是"打开白屏"那一类的线索。指标卡「PV · 入口访问」的措辞不变（它统计的就是入口）。

### 3.7 访问记录（`/proto/accesslog`）

| 区块 | 内容 |
| --- | --- |
| 筛选条 | 项目下拉（可搜索）、原型的级联下拉（选项目后才可筛）、时间范围（快捷：今天/近 7 天/近 30 天/自定义）、结果类型（正常/需密码/无权限/不存在）、关键字（IP/UA） |

## 4. 路由与菜单

**全部业务路由来自后端 `GET /menu/all`**（`accessMode: 'backend'`），前端只保留 vben 的 core routes（登录、403、404、500、根重定向）。菜单的 `component` 字段映射规则与排障方式见 [后端接口设计.md](./后端接口设计.md) §2.6。

**关键约定（写错即白屏或 404）**

1. 视图文件路径必须是 `apps/admin/src/views/<component>.vue`，数据库里 `component` 写 `/proto/project/index`（不带 `/views`，不带 `.vue`）。
2. 顶层菜单（`/proto/project` 这类）直接挂在根路由下、由 `BasicLayout` 包裹，**不要自己写 BasicLayout 组件**（vben 对带 children 的顶层路由会删掉其 component 以避免多层 BasicLayout）。
3. 需要"页面存在但侧栏不显示"的（项目详情、原型详情、个人中心），用 `hide_in_menu = true`。
4. 需要"菜单可见但点进去是 403"的（引导申请权限），用 `menu_visible_with_forbidden = true`。

## 6. 组件划分原则

**一条规则**：两处以上用到的能力收敛为一个通用组件，业务差异用 props 表达；基础组件遵守开闭原则（新增业务场景不改基础源码）。

| 通用组件 | 参数化维度 | 被谁复用 |
| --- | --- | --- |
| `HtmlZipUploader` | `accept` / `maxSize` / `autoStart` | §3.4 上传抽屉、§3.6 上传发布页 |
| `PublishDrawer` | `mode: 'create' \| 'newPrototype' \| 'append'`、`project?` / `prototype?` | 工作台、项目列表、项目详情、原型详情、上传发布页 —— **三种模式的差异全部由 props 表达，只有一份实现** |
| `PrototypePicker` | `projectId?` / `disabled` / `v-model` | §3.6 上传发布页、§3.7 访问记录筛选、§3.4 抽屉的"选择已有项目 + 新建原型"模式 |
| `ProtoStatusTag` / `ProtoAccessModeTag` | `status` / `accessMode` | 项目列表、原型列表、原型详情、工作台（**一套状态取值同时服务两级**，不写两套标签组件） |
| `CopyText` | `value` / `label` / `block` | 原型列表的访问地址列、原型详情、发布成功态 |
| `ReleaseTimeline` | `events` / `showActions` / `showPrototypeName` | 原型详情、项目详情（带原型名）、工作台最近动态 |
| `PublishTaskFloat` | `taskId` | 任何发起过发布的位置 |
| **`StatCard`**（M5-T1 新增，计划 §9.2 DEV-39） | `label` / `value` / `sub` / `loading` | 工作台 4 卡、访问记录页 5 指标卡 |

> **§6 这张表的参数化维度在 M3-T10/T12/T14 实施时被改了四处（原设计 + 修订说明，偏差 DEV-26）**，表里的原写法保留备查：
>
> 1. **`HtmlZipUploader`：`accept` / `maxSize` / `autoStart` → `accept` / `maxSizeBytes` / `disabled` / `task` / `uploading` / `uploadPercent`**。去掉 `autoStart` 是因为"选完文件就自己发出去"和 §3.4 的抽屉流程冲突——抽屉里用户选完文件还要填编码与版本说明，上传时机必须由父层决定；把进度做成 props 由父层喂，组件才能在 §3.6 的发布页与 §3.4 的抽屉里画**同一段**进度条而各自持有一份任务状态（对应 §8"轮询是一处实现，不写两份"）。`task` 就是接口设计 §5.3 的进度四字段，`null` 表示还没受理成功，此时只显示浏览器上传进度。
> 2. **`PublishTaskFloat`：`taskId` → 无 props**。浮层同时显示的是**多个**进行中任务（用户可以在 A 原型发布中又去发 B），`taskId` 只能描述一个；数据全部来自 §7 的 `usePublishTaskStore`，组件不持有状态也不自己轮询。挂在 basic 布局上、`Teleport` 到 `body`（布局里任何带 `transform` 的祖先都会让 `position: fixed` 的右下角跑偏）。
> 3. **`usePublishTaskStore`："任务成功/失败时清出" → 终态不清出，由用户点右上角 ✕ `dismiss(id)`**。终态那一刻正是用户要点链接/进详情的时候，自动清出等于把结果入口摘掉（违背"不做无出口的等待确认态"）；通知（antd notification）会自动消失，若行也一起消失，用户就没有第二次点它的机会了。进行中→终态的**通知**照设计给，行保留到用户主动关。抽屉正在看的那一条由 `heldId` 从浮层滤掉，同一任务不在两处各画一份进度。
> 4. **`ReleaseTimeline`：`events` / `showActions` / `showPrototypeName` → `prototypeId`（自己取数）+ `rolledBack` 事件 + `reload()` 方法**。它要画的不是"一串事件"，而是 **§5.4 版本行与 §5.8 事件行合成的两条流**（"发布"条目只有版本行给得出版本号与发布报告；"回滚/删除版本"只有事件行给得出，且回滚按钮的可用态要按 `isCurrent`/`status` 判）——把合成后的数组当 props 喂进来，父页面就得替组件懂这两张表的合并规则，而全项目只有原型详情需要它。因此 M3-T14 落成的是一个**按 `prototypeId` 自取数**的容器。**连带的两个消费点还没接**：§3.3 的项目详情"项目动态"（数据源 `GET /api/projects/{id}/events`，客户端函数 `getProjectEventsApi` 已写好并在 HTTP 层实测过，页面仍是空态）与 §3.1 工作台"最近动态"（数据源是 M5-T1 的 overview `recentEvents`）。这两处要的是"带原型名、无操作按钮"的呈现，与原型详情那个容器不同型；按 §3.7"两处以上才抽公共组件"，它们的呈现层**排到 M5-T1 与工作台一起做**——那时同时有两个真实消费者，能一次抽干净而不是抽两次（偏差 DEV-26 第 4 点、待接项见迭代实施计划 §9.1「M4/M5 待接与待复测清单」）。

**不自造的组件**：表格/分页/表单/抽屉/弹窗/消息提示一律用 vben 的 `useVbenVxeTable`/`useVbenForm` 与 ant-design-vue 原生组件，不自绘同类能力。

**新加说明性文案要克制**：页面/抽屉头部不铺副标题式说明（"保存后进入待处理并生成…"这类话是第一个被砍掉的）。规则只在**用户会因此做错事**的位置出现，例如"编码创建后不可修改"（就在编码字段旁）、"归档项目会使其下所有原型链接不可访问"（就在归档确认框里）。

## 8. 请求层

- 沿用 `apps/admin/src/api/request.ts`（含 401 刷新、错误提示拦截器），**不重写**。
- 契约类型从 `packages/shared/src/api-types/` 引入，与后端共用同一份定义：

```ts
// apps/admin/src/api/proto/prototype.ts
import type { PageResult, PrototypeListItem, PrototypeDetail } from '@protohub/shared';
import { requestClient } from '#/api/request';

export function getPrototypeListApi(params: PrototypeListQuery) {
  return requestClient.get<PageResult<PrototypeListItem>>('/prototypes', { params });
}

export function rollbackApi(prototypeId: string, releaseId: string, reason?: string) {
  return requestClient.post<PrototypeDetail>(`/prototypes/${prototypeId}/rollback`, { releaseId, reason });
}
```

- **上传超时单独放宽**：`requestClient.upload` 调用时传 `timeout: 0`（上传本身不设超时，靠 `onUploadProgress` 与用户取消控制），因为默认 10 秒超时对 100MB 包必然失败。

```ts
// apps/admin/src/api/proto/release.ts —— 发布是唯一带 multipart 的接口，单独抽出来
export function createReleaseApi(payload: CreateReleasePayload, file: File,
                                onProgress?: (percent: number) => void) {
  const form = new FormData();
  form.append('file', file);
  if (payload.projectId) form.append('projectId', payload.projectId);
  if (payload.project) form.append('project', JSON.stringify(payload.project));
  if (payload.prototypeId) form.append('prototypeId', payload.prototypeId);
  if (payload.prototype) form.append('prototype', JSON.stringify(payload.prototype));
  if (payload.note) form.append('note', payload.note);
  if (payload.force) form.append('force', 'true');
  return requestClient.upload<{ taskId: string; prototypeId: string; accessPath: string }>(
    '/releases', { file: form as any }, {
      timeout: 0,
      onUploadProgress: (e) => onProgress?.(Math.round((e.loaded / (e.total ?? 1)) * 100)),
    },
  );
}
```
  > 注意：`@vben/request` 的 `upload()` 内部**自己构造 FormData 并展开 data 对象**（数组会展开成 `key[0]`、`key[1]`）。若直接传一个已拼好的 `form`，需要按上述方式包一层；实现时先跑通一次真实上传再扩展，不要照抄伪代码。

- **发布任务轮询**：封装 `pollUploadTask(taskId, { interval: 1000, maxTries: 120, onTick })` 放在 `api/proto/release.ts`，组件不自己写 `setInterval`（避免页面切换后定时器泄漏）。轮询是被 `PublishTaskFloat` 与抽屉共用的一处实现，不写两份。

## 9. 权限在前端的四种用法

| 场景 | 写法 |
| --- | --- |
| 菜单与路由 | 不用写——后端 `/menu/all` 决定 |
| 按钮/操作项 | `v-access:code="['proto:project:delete']"` 指令 |
| 区块/Tab | `hasAccessByCodes(['system:user:list'])` 条件渲染 |
| 页内二态（如"该操作只有超管能做"） | `hasAccessByRoles(['super_admin'])` |

**红线**：前端隐藏不等于安全。所有隐藏的操作在后端都有对应 `@RequirePermission`，前端权限只负责"不让人看到点了会报错的按钮"。

## 10. 界面呈现规范

### 10.1 信息层级表（写样式前先定，避免同屏等重）

以「项目列表」页为例，先定层级再落样式（原型列表页用同一套层级，只是 L3 从项目名换成原型名）：

| 层级 | 元素 | 字号 / 字重 | 颜色 | 说明 |
| --- | --- | --- | --- | --- |
| L1 | 页面标题「原型项目」 | 20 / 600 | 主文本色 | 全页唯一最重元素 |
| L2 | 表头、区块标题、面包屑 | 14 / 500 | 次级文本色 | 不与 L1 竞争 |
| L3 | 单元格主数据（项目名称 / 原型名称） | 14 / 600 | 主文本色 | 每行唯一重元素；可点击进详情，带 hover 下划线 |
| L3 | 访问地址（链接） | 14 / 400 | 主题蓝 | 可交互，用色而非重量区分；出现在**原型**列表行 |
| L4 | 项目编码/原型编码、时间、状态文案 | 13 / 400 | 次级文本色 | 编码用等宽字体 |
| L4 | 原型数主值 `6` + 次级 `(已发布 5)` | 13 / 400 | 主文本 / 三级文本 | 同一格里用颜色区分主次，不加粗 |
| L5 | 辅助元数据（指纹前 8 位、无效链接的 routeKey 等） | 12 / 400 | 三级文本色 | 只在需要时出现 |

**规则**：不新增字号/色值，全部用 vben 主题 token（避免"AI 感"的根源是 token 漂移，而不是缺少效果）。同一信息只在一处出现：列表只放判断所需字段，说明文案、创建人等信息一律收进详情页。

### 10.2 状态与异常态（每屏都要有，不能只做"有数据"的样子）

| 状态 | 表现 |
| --- | --- |
| 加载中 | 表格骨架屏；统计卡用骨架块 |
| 空数据 | 插画 + 一句引导 + 主行动按钮（不留白） |
| 无权限 | 整页 403 页（vben 内置），页面内区块则整块隐藏而非显示"无权限"占位 |
| 请求失败 | 表格区展示"加载失败" + 重试按钮，不清空上一份数据 |
| 长文本 | 项目说明在列表不展示；详情页超长用展开/收起 |
| 大量数据 | 分页默认 20/页，可切 50/100；列排序走服务端 |

### 10.3 交互走组件库标准语义

| 场景 | 用什么 | 不要用 |
| --- | --- | --- |
| 行内多个操作 | 一个「⋯」Dropdown（原型图如此） | 一排文字按钮（会出现多个"删除"并排） |
| 新建/编辑/策略 | Drawer（右侧抽屉，原型图如此） | 全屏路由跳转 |
| 删除项目 | Modal.confirm + 输入名称二次确认 | 单次确认（不可逆操作） |
| 归档 | Modal.confirm 说明后果 | 直接执行 |
| 反馈 | message / notification（vben 内置） | 自绘 toast |
| 危险动作按钮 | 常态灰 + 悬停着色 | 一排常红按钮 |

## 12. 与原型图的逐项对照

> 原型图是按**两层模型**（项目＝一个访问链接）画的；本轮确认为**三层模型**（项目 → 原型 → 版本）。下表的"差异说明"里，凡带 **【模型变更】** 标记的都是层级变化带来的必然调整，不是实现取舍。

| 原型图元素 | 落地方案 | 差异说明 |
| --- | --- | --- |
| 顶部 logo + 「HTML 原型托管平台」 | vben header 的 logo + `VITE_APP_TITLE` | 无差异 |
| 顶部搜索框「搜索项目名称、产品编码…」 | **移到列表页工具栏** | 刻意偏离：避免改框架公共 header（§3.2） |
| 右上铃铛（通知） | 一期不做；预留位不显示 | 无通知渠道（邮件/企微在 P1） |
| 右上头像 + 姓名下拉 | vben 内置用户下拉，菜单项改为「个人中心 / 退出登录」 | 无差异 |
| 左侧菜单 5 项 | 后端菜单表下发，顺序与图标对齐 | 无差异 |
| 页面标题 + 一句说明 + 右上蓝色按钮 | 页面头部区（标题 L1 / 说明 L4 / 按钮 primary） | 无差异 |
| 列表 6 列（项目名称/产品编码/访问地址/最近更新/状态/操作） | 项目列表改为 **项目名称 / 项目编码 / 原型数 / 最近更新 / 状态 / 操作** | **【模型变更】** 一个项目对应多条链接，项目行放单条"访问地址"会误导，该列下移到项目详情的原型列表；「产品编码」正名为「项目编码」 |
