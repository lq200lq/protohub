# ProtoHub 设计文档

> 状态：设计待评审 ｜ 日期：2026-10-06 ｜ 适用：vben-admin 5.7.0 / Node 24 / PostgreSQL 17

HTML 原型托管平台（ProtoHub）的设计文档集。文档只描述**设计**，实现期的修正与新决策回写这里，代码与文档不一致时以文档为准（或先改文档再改代码）。

> **核心模型（三级）：项目 → 原型 → 版本。**
> 一个项目下可以有多个原型，**每个原型是一条可独立分享的链接**（`/p/{项目编码}/{原型编码}`），各自持有自己的版本历史、当前生效版本与访问策略。
> 项目是容器（管归档与成员范围），原型是分享与鉴权的最小单位，版本是不可变快照。详见 [平台设计方案.md](./平台设计方案.md) §4。

## 阅读顺序建议

- **要动手写代码**：平台设计方案 → 数据库设计 → 后端接口设计 → 前端设计（按此顺序实现即可，里程碑见主文档 §9）。
- **只关心产品形态**：平台设计方案 §1~§4 + 前端设计 §3 页面清单。
- **只关心权限**：权限模型设计（全文）+ 数据库设计 §4.3 权限相关表。

## 权威边界（避免同一事实两处写、两处漂）

| 事实 | 唯一出处 | 其他文档的处理方式 |
| --- | --- | --- |
| 表结构 / 字段 / 索引 | 数据库设计.md | 只引用表名与字段名，不复制 DDL |
| API 请求响应结构 | 后端接口设计.md | 只写"调用哪个接口"，不复制字段 |
| 权限码取值 | 权限模型设计.md | 其他文档用权限码时直接引用标识符 |
| 页面与路由 | 前端设计.md | 主文档只列模块名 |
| 版本 / 磁盘目录布局 | 原型发布与访问机制.md | 部署文档只写路径常量 |
| 决策结论与理由 | 平台设计方案.md §8 决策表 | 被决策约束的细节在各专题文档里展开 |

## 与代码仓库的关系

```
protoHub/
├── docs/                     ← 本目录，设计唯一依据
├── apps/
│   ├── admin/                ← vben-admin 5.7.0（基于 apps/web-antd 裁剪）
│   └── server/               ← NestJS + Fastify 服务端
├── packages/                 ← 共享类型与常量（前端可直接引用后端的契约类型）
└── deploy/                   ← nginx 配置、pm2 配置、初始化 SQL
```
